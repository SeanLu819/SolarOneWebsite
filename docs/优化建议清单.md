### ✅ N-32 静态资源未哈希 → 回访重复校验 —— **已解决（2026-09-12，P0）**

**症状**：live 探测生产静态资源（`HEAD /static/css/base.css`）得到
`X-Vercel-Cache: HIT`（边缘已缓存）但 `Cache-Control: public, max-age=0, must-revalidate`
—— 回访用户每次仍要回源校验，CSS/JS/图片无法长缓存。

**根因（两层）**：
1. 旧 `build.sh` 注释称「`vercel.json` 必须含 `handle: filesystem`」曾被怀疑静态未走边缘 —— **实测已走边缘（HIT）**，该疑虑排除。
2. 真正的根因：**Django 6.0 已移除 `STATICFILES_STORAGE` 设置项且静默忽略**。项目此前只在旧设置项里指派存储后端，等于**没生效** → collectstatic 一直产出**未哈希**文件；Vercel 对无哈希文件名只给 `max-age=0`。

**修复**：改用 `STORAGES` 字典，并**按环境条件化**：
- 生产（`IS_VERCEL=1`）：`whitenoise.storage.CompressedManifestStaticFilesStorage`（内容哈希文件名 → Vercel 边缘自动 `immutable, max-age=31536000`）。
- 本地：`django.contrib.staticfiles.storage.StaticFilesStorage`（普通）—— 本地 dev server 走 WhiteNoise finders 从源码 `static/` 直接服务，文件名**没有**被哈希重命名；若本地也哈希，`{% static %}` 产出的哈希 URL 在 finders 下会 **404**。

**配套**：`base.html` 去掉手动 `?v=19`（哈希已自动破冰）；`pages/tests.py` 两个图片路径断言改为**哈希无关**（剥离 12 位内容哈希再比对）。

**验证**：临时 `STATIC_ROOT` 跑 collectstatic 确认生成 `css/base.<hash>.css`；L1 73 tests OK、L2 ALL CHECKS PASSED（本地为普通存储，故无回归）。

### ✅ N-34 Vercel 函数包 270 MB 超限，部署被阻塞 —— **已解决（2026-09-12，P0）**

**症状**：v1.5.2 push 后 Vercel 构建失败 ——
`Total bundle size (270.23 MB) exceeds the maximum function size (225 MB)`。

**根因**：`vercel.json` 的 `functions["api/index.py"]` 写了 `"includeFiles": "**"`。
读 `@vercel/python@latest/dist/index.js` 证实构建器顺序如下：

```js
const files = await glob("**", { cwd: workPath, ignore: [ ...predefinedExcludes, ...excludeFilesPatterns ] });
for (const pattern of includeFilesPatterns) {
  Object.assign(files, await glob(pattern, workPath));   // ← 不带 ignore，覆盖排除结果
}
```

即 **`includeFiles` 在 `excludeFiles` 之后执行且无视排除**，`**` 等于强制把整个仓库
打进 Lambda：源码 `static/`（58 MB）+ collectstatic 产物 `staticfiles/`（59 MB）
+ 依赖（~64 MB）—— 而静态资源本来就已经由边缘 CDN 通过 `public/static/` 服务
（实测 `X-Vercel-Cache: HIT`），等于**同一份资源上线两次**。
（`public/**` 已在构建器 `predefinedExcludes` 内，不是问题。）

**修复**（`vercel.json`）
- 删掉 `"includeFiles": "**"`；重型目录改走 `excludeFiles`：
  `static/**`、`staticfiles/**`、`media/**`、`docs/**`、`screenshots/**`。
- **静态清单必须留在函数包内**：`CompressedManifestStaticFilesStorage` 运行时要读
  `staticfiles.json` 才能把 `{% static %}` 映射成哈希 URL。用
  `"includeFiles": "staticfiles/staticfiles.json"` 精确保留（该字段最后执行，
  正好不会被上面的排除清掉）；Django 项目构建器自身也会把清单复制回 `STATIC_ROOT`。
- 预计 270 MB → ~150 MB。验证手段：临时加环境变量 `VERCEL_ANALYZE_BUILD_OUTPUT=1`
  让构建日志打印函数包体积明细；兜底方案 `VERCEL_SUPPORT_LARGE_FUNCTIONS=1`
  （Fluid compute，上限 5 GB），但属治标。

#### ⚠️ 二次踩坑（v1.5.4 修复）：`excludeFiles` 必须是一条 **string**，不能是数组

上述修复首次 push 后 Vercel **在构建前**即失败（耗时仅 15s），报
`A Configuration error — Vercel couldn't load a valid project configuration`。
**与体积无关**，是 `vercel.json` **schema 校验不过**。

拉官方 schema 核实（`curl https://openapi.vercel.sh/vercel.json`）：

```
/properties/functions/patternProperties/^.{1,256}$/properties/excludeFiles
  → { "type": "string", "maxLength": 256 }
/properties/functions/patternProperties/^.{1,256}$/properties/includeFiles
  → { "type": "string", "maxLength": 256 }
而该 patternProperties 节点是 "additionalProperties": false
```

即：**`excludeFiles` / `includeFiles` 各只能是一个 glob 字符串**，写成
`["static/**", ...]` 数组 → 类型不符 → **配置层直接拒绝，连构建都不开始**。
（`$schema` 本身是顶层合法属性，不是问题；`builds` + `functions` 互斥也不是本例原因。）

**一条字符串怎么排除多个目录 → 用花括号展开**
`normalizeGlobs()` 的实现在构建器里是：

```js
function normalizeGlobs(value) {
  return Array.isArray(value) ? value.filter(i => typeof i === "string")
       : typeof value === "string" ? [value] : [];
}
```

**字符串只会被包成 `[value]`，不会按逗号拆分**。而它最终喂给
`@vercel/build-utils` 的 `glob()`（底层 = npm `glob` / minimatch），
minimatch 原生支持 `{a,b}` → 因此写成：

```json
"excludeFiles": "{static,staticfiles,media,docs,screenshots}/**"
```

**实测验证**（node + 真实 `glob` 包，合成一棵与仓库同构的目录树，复刻构建器顺序
`glob("**", {cwd, ignore:[...predefined, ...exclude]})` 再 `Object.assign(includeFiles)`）：

| 模式 | 包内文件数 | 泄漏的重型目录文件 |
|---|---|---|
| `{static,staticfiles,media,docs,screenshots}/**` | 7 | **0** |
| `{static,staticfiles}/**` | 10 | **0** |
| 不排除（等价旧 `includeFiles: "**"`） | 16 | 3 个 `static*` 文件 |

另加一层保险：构建器自身还有

```js
if (djangoStatic?.manifestRelPath) {
  files[djangoStatic.manifestRelPath] = new FileFsRef({ fsPath: join(workPath, djangoStatic.manifestRelPath) });
}
```

—— Django 项目会**主动把 `staticfiles.json` 塞回函数包**（`manifestRelPath` 由构建器
自己的 collectstatic 步骤算出）。所以 `includeFiles` 在此属**冗余保险**，保留无害，
可防「框架检测未走到 Django 分支」的边角情况。

**校验手段（可复用）**：下载官方 schema 后写脚本断言
① 顶层键都在 `properties` 内；② `functions` 子树逐键比对 `type` / `maxLength` /
`additionalProperties`。该脚本能**准确复现** Vercel 的报错
（对旧配置输出 `excludeFiles : 期望 string，实际 list`）。

**新增离线守卫（v1.5.4）**：`pages/tests.py` → `VercelConfigTests`（4 项，不联网）
- `test_top_level_keys_are_known`：顶层键必须都在 schema 已知集合内；
- `test_function_options_match_schema_types`：**`excludeFiles` / `includeFiles` 必须是
  `str` 且 ≤256 字符**，选项键不得越出 `additionalProperties: false` 的白名单
  —— **本项正是 v1.5.3 事故的直接拦截器**；
- `test_heavy_static_trees_excluded_and_manifest_kept`：断言 `static/**` 与
  `staticfiles/**` 被排除、`staticfiles/staticfiles.json` 被保留（体积修复的核心不变量）；
- `test_brace_glob_expansion_helper`：`_expand_braces()` 辅助函数自身的行为。
- 结果：L1 **88 → 92 tests OK（skipped=2）**。

**「清理无用文件」的结论：没有可清理项。** 写了一次 DB 感知的孤儿审计
（引用源 = 全部模板/CSS/JS/`seed_data.json`/`*.py` + `db.sqlite3` 每一张表的文本列），
`static/` 与 `media/` 下**孤儿 0 个**：377 张图 + 17 个 PDF 全部在用。
先前一次仅比对文本的审计报出 15 MB「孤儿」全是**误报**（它们由 DB 字段引用）。
结论：本项目的体积问题**不在资源冗余，而在打包范围**。

### ✅ N-35 静态资源移出函数包后，请求期图片解析会失效 —— **已解决（2026-09-12，P0）**

**症状（若只做 N-34 会引入的坑）**：`pages/views/utils.py` 在**请求期**扫描磁盘：

- `_find_static()` → `_build_static_file_set()`：`os.walk(STATIC_ROOT + STATICFILES_DIRS)`
  建候选路径存在性集合；
- `_list_static_dir()` / `_list_product_dir_images()`：`os.listdir` 枚举目录，
  用于项目相册自动发现与「卡片位优先非 banner 图」逻辑。

`static/`、`staticfiles/` 被排除出函数包后这些目录在运行时**不存在** →
`_find_static` 全 False → `_product_image_url` 会回退到 `/media/...`（Vercel 上同样
不存在）→ 产品图、项目相册**静默变空**。

**修复**：新增构建期**名字索引**（只存文件名，不含字节，约 20 KB）
- `pages/static_index.py`：`build_index(root)` + `render_module()`，
  `python -m pages.static_index --root staticfiles --out pages/static_index_data.py`；
- `build.sh` 在 collectstatic 之后生成；`pages/static_index_data.py` **git-ignored**
  （与 `pages/seed_data.py` 同一套约定，每次部署重建）；
- `utils._load_static_index()` 一次 import，`_build_static_file_set()` /
  `_list_static_dir()` 都改为**索引 ∪ 磁盘扫描** —— 本地开发与 CI 行为不变；
  `_list_product_dir_images()` 改为复用 `_list_static_dir()`，删掉自带的
  `os.listdir` 循环。

**验证**：写脚本模拟 Vercel 运行时（`STATICFILES_DIRS=[]`、`STATIC_ROOT` 指向不存在的
目录），与「磁盘存在」的基线逐项对照 —— 六个页面类型全部 200 且静态图数量**完全一致**
（`/`=6、`/products/`=9、`/projects/`=11、`/about/`=5、`/contact/`=4、`/news/`=1，
项目详情页相册 =12），`media-src=0`、空 `src=0`，**零回归**。

**新增守卫**：`StaticIndexBuildTests`(3) + `StaticIndexFallbackTests`(4) +
`GeneratedStaticIndexCoverageTests`(1) —— 最后一项断言索引覆盖 `static/` 下
**每一个**已提交文件，防止索引过期导致线上静默丢图。CI 已同步生成索引，让该断言真正生效。
