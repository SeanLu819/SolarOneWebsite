# 项目优化建议清单

> 已完成的优化：🔴 #1 重复函数、🟠 #4 产品白名单、🟠 #5 图库映射、🟡 #15 db.sqlite3、🟡 #16 seed_data.py

---

## 架构优化

### #2 views.py 单体巨石（1197 行）

**现状：** `pages/views.py` 包含所有视图函数、数据加载、图片解析、i18n 字典、缓存逻辑、类别映射。

**建议拆分：**
```
pages/
  views/
    __init__.py          # 导入所有视图
    products.py           # product_list, product_detail
    projects.py           # project_list, project_detail
    contact.py            # contact 视图
    utils.py              # _find_static, _list_static_dir, 图片解析
    enrich.py             # _enrich_product, _enrich_project
    i18n.py               # _SIDEBAR_I18N, _SIDEBAR_CAT_TO_PRODUCT_CAT
    seed_loader.py        # _load_seed, _get_products_from_json, _get_projects_from_json
```

---

### #3 _SIDEBAR_I18N 硬编码翻译

**位置：** `pages/views.py` 中大约 200+ 行硬编码的 6 语言翻译字典

**现状：** 与 Django 内置的 `.po/.mo` 翻译系统完全独立。每次增加语言/文本需要改代码。

**建议：** 迁移到 Django 标准的 `.po` 文件：
```python
# 模板中使用
{% trans "Products" %}
{% trans "Projects" %}
```

或者至少将 `_SIDEBAR_I18N` 提取到单独的 `i18n.py` 模块中。

---

### #6 _COMPARE_IMAGE_SLUGS 硬编码

**位置：** `pages/views.py` 约 L866 行

**现状：** 只有 `football-field-led-retrofit` 有对比图，新增项目需改代码。

**建议：** 在 Project 模型中增加 `compare_old_image` 和 `compare_new_image` 字段，从管理后台配置。

## 代码质量

### #7 OverwriteStorage 定义但从未使用

**位置：** `pages/storage.py`

**现状：** 整个类的唯一场景是防止 Django 哈希后缀，但实际哈希后缀文件仍然大量产生（Django 默认行为）。

**建议：** 删除该文件，或真正在 ImageField 上使用它。

---

### #8 ProductsPageCard 模型可能未使用

**位置：** `pages/cards.py`

**现状：** 定义了 `ProductsPageCard` 模型，但需确认 products 页面是否真的使用这个模型。

**建议：** 在 views 中搜索 `ProductsPageCard` 引用，如果未使用则删除。

---

### #9 django_cleanup 被注释掉

**位置：** `solarone/settings.py` L51

**现状：**
```python
# 'django_cleanup.apps.CleanupConfig',  # should go last
```

**建议：** 要么安装 `django-cleanup` 包并启用（自动清理 ImageField 旧文件），要么删除注释避免误导。

---

### #10 import os 在函数内部

**位置：** `_list_product_dir_images` 等函数内部有 `import os` 语句

**现状：** 文件顶部已有 `import os`，函数内部重复导入是冗余的。

**建议：** 删除函数内部的 `import os`，统一使用文件顶部的导入。

---

### #11 缺少类型注解

**现状：** 整个项目无 type hints。

**建议：** 至少对核心函数添加类型注解，提高可维护性：
```python
def _find_static(rel_path: str) -> bool: ...
def _enrich_product(product: Product, lang: str) -> None: ...
def _product_image_url(product: Product, field_name: str) -> str: ...
```

---

### #12 缓存策略不一致

**位置：** `pages/views.py`

**现状：** 同时使用进程级 dict 缓存（`_enriched_products_cache`）和 Django cache API（导入但未实际使用）。

**建议：** 
- 本地开发：使用进程级 dict 缓存（当前方案）
- Vercel 生产：进程级缓存无效（无状态），应使用 Django cache 或直接依赖 seed_data 模块导入

---

## 安全 & 运维

### #13 SECRET_KEY 环境变量未设置

**位置：** `solarone/settings.py` L28

**现状：**
```python
SECRET_KEY = os.environ.get('VERCEL_SECRET_KEY', 'django-insecure-...')
```

**建议：** 在 Vercel 环境变量中设置 `VERCEL_SECRET_KEY`，确保 CSRF/session 安全。

---

### #14 缺少 .env.example

**现状：** 无文档说明需要哪些环境变量。

**建议：** 创建 `.env.example`：
```env
# Required
SECRET_KEY=your-secret-key-here

# Optional
DEBUG=True
VERCEL=1
```

---

### #17 index.py 有大量调试日志

**位置：** `index.py` L30-L72

**现状：** 每次冷启动都输出文件列表到 stdout。

**建议：** 将 `print()` 改为 `logging.debug()`，或添加 `if settings.DEBUG:` 条件。

---

### #18 Visitor 追踪在每次 GET 请求写 DB

**位置：** `pages/middleware.py`

**现状：** 每次请求都写入 `Visitor` 表。Vercel 上 SQLite 在 `/tmp/`，每次冷启动丢失。

**建议：**
- 降低写入频率（如每 5 分钟一次/每 IP 每天一次）
- 或使用外部分析服务（Google Analytics / Plausible）
- 或在 Vercel 上完全禁用 Visitor 追踪（无意义）
