## 1. 当前响应式现状梳理

### 1.1 断点体系（多断点混用，未统一）

| 断点 | 位置 | 用途 |
|---|---|---|
| `≥768px` | base.css | 主断点：显示完整导航链接①、隐藏汉堡、产品网格 1→2 列、hero-stats 2→4 列、about-stats 2→4 列、contact-grid 1→2 列、footer-grid 1→2 列、project-card 竖→横、section padding 递增 |
| `≤767px` | base.css | 仅 hero 专属（隐藏角标装饰、padding/min-height 调整） |
| `≤900px` | base.css + 各页 | 侧栏类页面 `sidebar-layout` 折单列、详情页 `detail-grid` 折单列、`.detail-info-grid.has-compare` 折单列、`.detail-request-sample` 折单列 |
| `≥1024px` | base.css | 产品网格 2→3 列、footer-grid 2→4 列、section padding 140px |
| `768–1024px` | base.css:1659 | 产品页侧栏专属窄栏 `260px 1fr`（`!important`） |

① **注意：`@media (min-width:768px){.nav-links{display:flex}}` 是无效规则**——`.nav-links` 基础样式本身就是 `display:flex`（见 1.3 / P0-1）。

### 1.2 布局
- 列表/详情页：左侧 sticky 侧栏（240/270px，模板内联）+ 主内容；`≤900px` 侧栏变普通块，按 DOM 顺序排在主内容**之前**。
- 表格（能源/订购信息）：外层 `overflow-x:auto` 容器，移动端可横滑 ✅。
- `.container` 1280px，padding 16→32px。

### 1.3 导航
- HTML 结构（base.html:77-110）：`nav-inner` 单行 flex 容器内依次为：
  **logo → nav-links(Home/Products/Projects/News/About) → nav-cta(Contact Us) → theme-toggle → lang-switch → hamburger**
- CSS（base.css:340-345）：`.nav-inner{display:flex; justify-content:space-between; gap:24px}`，**无 flex-wrap**。
- `.nav-links`（base.css:355-359）= `display:flex` **始终显示**；`.hamburger`（base.css:389-398）= `display:flex`，仅 `≥768px` 隐藏。
- 移动面板（base.html:62-73）：右侧滑出抽屉，含 Home/Products/Projects/News/About 五项。

### 1.4 字号（后台覆盖默认）
- base.css:29-36 默认全是响应式 `clamp()`（如 `--fs-hero-title: clamp(36px,7vw,72px)`）；
- 但 base.html:41-53 用后台 SiteConfig 的**固定 rem** 覆盖，数据库当前值：
  `hero_title=3.5rem(56px)`、`section_title=2.25rem(36px)`、`fs_nav=17px`、`fs_body=1.05rem` 等 → 手机端实际是固定字号，clamp 失效。

### 1.5 交互
- 滚动显现 `.reveal`（IntersectionObserver）、数字滚动、轮播（首页 5s / 详情 3-4s，尊重 prefers-reduced-motion）、侧栏三级折叠（`aria-expanded` 同步）、语言切换（cookie+i18n-prefix）、主题切换（localStorage 防 FOUC）。

## 2. 问题清单

### 🔴 P0 — 移动端基本不可用（用户实机已确认）

#### P0-1 导航栏溢出：`.nav-links` 在移动端从未隐藏，汉堡被挤出视口
- **现象**：看不到汉堡按钮；只能看到 logo + Home/Products/Projects/News，About 及右侧全部不可见。
- **根因**（代码依据）：
  - `base.css:355-359`：`.nav-links{display:flex}` 为默认值；`@media(min-width:768px){display:flex}` 只重复不隐藏 → **移动端 5 个链接始终显示**，与汉堡按钮并存。
  - `base.css:340-345`：`.nav-inner` 单行 flex、`gap:24px`、无 `flex-wrap`。
  - `base.css:319`：`body{overflow-x:hidden}` → 溢出的内容被静默裁掉，**页面不会出现横向滚动条，用户无法感知溢出**。
  - flex 顺序：汉堡位于容器最右端 → 溢出区域，点不到；移动菜单（mobile-panel）结构完好但入口不可达。
- **估算**：iPhone 14 390px 下，logo + 5 链接 + CTA(≈110px) + 主题(36px) + 语言(≈70px) + 汉堡(44px) + gaps 合计远超 390px。

#### P0-2 移动端无 Contact 入口
- `base.html:66-72`：移动面板仅 5 项（Home/Products/Projects/News/About），**无 Contact**。
- 叠加 P0-1（顶部 nav-cta 溢出不可见）→ 手机端联系入口实际缺失。

#### P0-3 Products / Projects 移动端首屏被分类树占满
- **现象**（用户实机）：进入产品/项目列表页，首屏全是左侧分类导航，下滑很久才见内容。
- **根因**：
  - 折叠规则**存在且生效**（`≤900px` → `sidebar-layout` 折单列，base.css:1650-1658 + 各模板内联 style），手机上确为单列；
  - 但 **DOM 顺序 sidebar 在 content 之前**（products.html:25-61、projects.html:25-49）→ 折叠后分类树整棵排在内容上方；
  - 分类树很长（8 大类 × 每类多系列 × 有的三级子系列），且**无收起机制** → 390px 手机上要滚过整棵树。
- 用户期望：手机上侧栏应收起为"筛选/目录"可折叠入口，且内容应优先展示。

#### P0-4 后台固定字号覆盖响应式 `clamp()`
- 见 1.4。手机上 hero 标题固定 56px（多行堆积、首屏被下压）；副页 section-title 固定 36px 偏大；`--fs-nav` 17px 加剧导航溢出。
### 🟠 P1 — 三端一致性 / 布局问题

#### P1-5 断点体系割裂（768 / 900 / 1024 三套并存）
- 折叠断点 900px 与内容网格断点 768px 不一致：平板竖屏 768–899px 时侧栏已折叠（900 规则）、内容已是 2 列（768 规则）→ 体验割裂；产品页另有 `768–1024px` 的特判（base.css:1659-1663）。

#### P1-6 详情页 901–1024px 双列过挤
- `product_detail.html:846-880` 仅 `≤900px` 才折单列；901–1024px 下 240px 侧栏 + `detail-grid` 1.2fr/1fr + `detail-specs` 2 列（模板 L653-654）→ 主区不足 ~650px 时规格/文字拥挤。

#### P1-7 products-banner 超窄屏裁切
- `products.html:143` 固定 `aspect-ratio:1920/442` + `overflow:hidden`：360px 屏高≈83px、320px 屏高≈73px，banner 文字（label+36px 标题+留白）可能被裁。

#### P1-8 项目卡片标题移动端单行截断
- `.project-card-title`（base.css:1082-1084）`white-space:nowrap; text-overflow:ellipsis`：移动端全宽下也不换行，长项目名被截成"…"，而移动端本有空间换行。

#### P1-9 `.reveal` 区块依赖 JS 才可见
- `base.css:1666-1674` 初始 `opacity:0`，靠 JS 加 `.is-visible`。无 JS / JS 报错时首页预览、about 各区块、news 卡片**整块不可见**（SEO / 无障碍 / 低端机风险）。

### 🟡 P2 — 轻微 / 可维护性

#### P2-10 内联 grid 样式 + `!important` 纠缠
- `products.html:25`、`product_detail.html:29`、`projects.html:25`、`news.html:14`、`project_detail.html:29` 均内联写死 `240/270px 1fr`，靠 base.css `!important` 覆盖，改布局需同步多处；`contact.html:32` 内联 `grid-template-columns:1fr 1fr` 优先级高于 base.css 的 `.contact-grid` 断点。

#### P2-11 RTL（阿拉伯语）未适配绝对定位元素
- `products-banner-content{left:32px}`（products.html:174）、`series-hero-content{left:32px}`（product_detail.html:401 / product_series.html）为硬编码左侧，RTL 下仍靠左（RTL 目前只覆盖 nav/footer/hero-content）。

#### P2-12 其他小问题
- `base.css:198` `[dir=rtl] .nav-actions` 引用了 HTML 中不存在的类（死规则）。
- 静态资源版本号 `?v=6`（base.html:35）固定：后续改 CSS 需 bump，否则浏览器/代理缓存旧样式。
- 首页 hero 标题当前 DB 值长度较长，移动端固定 56px 下约需 4-5 行。

### 🔴 新增 P0 — 移动端体感直接受损

#### N-1 iOS 输入框聚焦自动放大，且不会回弹
`base.css:1264-1267` → `.form-group input, textarea { font-size: 15px }`。iOS Safari 对 `font-size < 16px` 的输入框会在聚焦时**自动放大整页**，失焦后**不还原**。联系表单是本站核心转化入口，iPhone 上 100% 复现。
→ **修复：`font-size: 16px`**（视觉差异极小，`padding:14px 16px` 已足够）。

#### N-2 移动端隐藏 `lang-switch` 会导致语言切换入口消失
原 F2（隐藏 `.lang-switch`）+ F3（面板只补 Contact）组合，会让手机端**彻底失去切换语言的能力**（站点六语种，核心功能）。
→ **修复：语言 / 主题 / Contact 一并移入移动面板**（已并入 F2'/F3'）。

### 🟠 新增 P1 — 三端一致性 / 性能 / 无障碍

#### N-3 导航 DOM 双份（P0-2 的真正根因）
`base.html:81-87`（`.nav-links` 5 项）与 `base.html:66-72`（`.mobile-panel-links` 5 项）是两份独立维护的列表。只补第 6 项是治标，下次加导航项必然再次漂移。→ 抽 `includes/nav_items.html` 共用（F3'）。

#### N-4 Hero 与首屏大图无 `srcset`，移动端下载 1920px 原图
`home.html:15-19`：三张 hero 均为 1920px 源文件（`hero-main-2.webp` 252KB、`hero-main-3.webp` 226KB、`hero-main-1.webp` 77KB ≈ **555KB**）。第 2/3 张虽标 `loading="lazy"`，但它们是 `position:absolute; inset:0` 铺满首屏 → **仍在视口内，lazy 不生效，三张全量下载**。
→ **修复：加 `srcset`/`sizes` 提供 768/1280/1920 三档；或让非首帧 slide 真正延迟加载。**

#### N-5 Google Fonts 阻塞渲染 —— 直接影响本地实机测试可行性
`base.html:25-27` 以普通 `<link rel=stylesheet>` 同步加载 `fonts.googleapis.com`。
- 生产：海外用户可用，但仍是**阻塞渲染的第三方请求**，弱网下首屏白屏。
- **本地测试（§6.4 用 iPhone 连局域网）：国内网络访问会长时间挂起/超时，直接拖慢甚至卡死验收流程。**
→ **修复：异步加载（`media="print" onload="this.media='all'"`）+ 系统字体兜底，或自托管 woff2。**

#### N-6 无 `viewport-fit=cover` / 无安全区适配，Cookie 横幅被 Home Indicator 遮挡
`base.html:428` Cookie 横幅 `position:fixed; bottom:0`，`z-index:9999`，**无 `env(safe-area-inset-bottom)`**。iPhone 上"Accept / Reject"按钮会被底部小黑条压住。
→ **修复：`<meta name=viewport content="..., viewport-fit=cover">` + 横幅 `padding-bottom: calc(20px + env(safe-area-inset-bottom))`。**

#### N-7 RTL 下移动面板仍从右侧滑出
`base.css:402-406` → `.mobile-panel{right:0; transform:translateX(100%)}`，汉堡也在 `nav-inner` 最右。阿语（RTL）下抽屉应从**左**侧滑出（P2-11 只覆盖 banner，未覆盖抽屉）。
→ **修复：`[dir=rtl] .mobile-panel{right:auto; left:0; transform:translateX(-100%)}` + 打开态同步。**

#### N-8 `scroll-behavior: smooth` 未在 reduced-motion 下关闭
`base.css:312` `html{scroll-behavior:smooth}`，`base.html:323` `scrollTo({behavior:'smooth'})`。全站仅 `.reveal` 与 hero 光晕做了 reduced-motion 处理，**平滑滚动没有**。
→ **修复：`@media (prefers-reduced-motion: reduce){ html{scroll-behavior:auto} }`，JS 侧同步判断。**

#### N-9 触摸目标小于 44×44
`.theme-toggle` **36×36**（base.css:134）、`.lang-switch-btn` 约 **34×30**（base.css:152-164）；仅 `.hamburger` 为 44×44 ✅。低于 WCAG 2.5.8 / Apple HIG 建议值。
→ **修复：移动端媒体查询内用伪元素扩大命中区（视觉尺寸不变）。**

#### N-10 无全局长词换行保护
仅 base.css:1436、1611 两处有 `word-break: break-word`，**无全局兜底**。邮箱、`contact_whatsapp`、产品型号（如 `SL-FL-1000W-RA90`）在 320px 下可能撑破容器 —— 且因 `overflow-x:hidden` 被**静默裁切、用户无法感知**（与 P0-1 同一失效模式）。
→ **修复：`body{overflow-wrap:anywhere}`。**

#### N-11 `100vh` 仍用于平板
`base.css:504` `@media(min-width:768px){.hero{min-height:100vh}}` —— iPad Safari 工具栏收起/展开时会溢出。移动端已用 `60svh`（正确），平板档未跟进。
→ **修复：`min-height:100svh`（带 `100vh` 降级）。**

#### N-12 验证断点缺少两档

#### N-18 项目卡片图片移动端被裁 12px（v1.1.6 复核发现，L2 实测）
`base.css:1047-1056` → `.project-card-img { width: 100%; height: 180px; margin: 12px 12px 0; }`。
父级 `.project-card`（`base.css:1026-1035`）是 `display:flex; flex-direction:column; overflow:hidden`。
**`width:100%` 与左右各 `12px` margin 叠加 → 实际宽度 = 容器内容宽 + 24px**，右侧超出 12px 被 `overflow:hidden` 静默裁掉。

L2 实测（390 档）：卡片 `clientWidth=356`、`scrollWidth=380`；`.project-card-img` 左偏移 `L=13`（border 1 + margin 12）、宽 `356`、右边缘 `369 > 358`。

- **影响**：项目卡片图片右侧被裁 12px，且左右留白不对称（左 12px 可见、右被切）。
- **为何一直没被发现**：与 P0-1 **同一失效模式**——`overflow:hidden` 让它既不产生横向滚动条，也不触发 L2 的页面级溢出断言。
- **桌面不受影响**：`@media(min-width:768px)` 下已改为 `width:45%; margin:0 0 0 12px`（`base.css:1057-1064`），不溢出。
- **修复（移动端限定，桌面零改动）**：在 `@media (max-width:767px)` 内覆盖 `width:auto`（flex column 下子项会自动 stretch 填满并扣掉 margin）。**不要**改基础规则的 `width:100%`——它被桌面档的 `45%` 覆盖，改基础值易误伤。
- **v1.1.7 已修复**：`base.css:1065-1072` 新增 `@media (max-width:767px){ .project-card-img{ width:auto } }`。修复后卡片 `scrollWidth == clientWidth`，内部溢出消失。
- ⚠️ **但 N-18 只是表象**：修掉后 320 档仍溢出 44px，继续追查得到真正的根因 **N-21**。

#### N-21 侧栏 grid 轨道被 min-content 顶爆（v1.1.7 复核发现，320/360 档整页溢出 44px）
`base.css:1746-1750` → `@media (max-width:900px){ .sidebar-layout{ grid-template-columns: 1fr !important } }`。

**`1fr` 等价于 `minmax(auto, 1fr)`，其最小值取轨道内容的 min-content**，而不是 0。实测 320 档：

```text
div.sidebar-layout   rectW=288  clientW=288  → grid-template-columns: 346.531px  ← 轨道被顶爆
  div.sidebar-content                  rectW=347
    div.projects-grid (flex)           rectW=347
      a.project-card                   rectW=347   ← min-content ≈347px
div.container        rectW=320  scrollW=364        ← 整页溢出 44px
```

- **触发链**：`.project-card` 的 min-content ≈347px → grid 轨道 `1fr` 的 auto 最小值被顶到 346.53px → 轨道（346.53）远大于容器（288）→ 整页横向溢出 44px → 被 `body{overflow-x:hidden}` **静默裁切**（与 P0-1、N-18 同一失效模式）。
- **为何只影响 320/360**：容器可用宽 = 视口 − 32(padding)。320 档仅 288、360 档 328，均 < 347 → 顶爆；≥390 档容器 ≥358 > 347 → 不触发。这也是它长期没暴露的原因。
- **修复（标准解法）**：`grid-template-columns: minmax(0, 1fr) !important;` —— 允许轨道收缩到 0。
- **注意**：`375px` 档容器 = 343 < 347，**理论上也会顶爆**（L2 未覆盖 375 档，建议补档，见 N-12）。

#### N-19 L2 横向溢出断言基准失效（v1.1.6 复核发现）
`scripts/e2e/run_checks.py` 用 `document.documentElement.scrollWidth - window.innerWidth <= 1` 判溢出。
但 `is_mobile=True` 的移动端模拟下，**内容过宽会把 layout viewport 一起撑大**（实测：设定 320 档 → `window.innerWidth` 报 **364**），于是 `scrollWidth - innerWidth` 恒为 0 —— **溢出被自我掩盖，断言永远绿**。
→ **修复：基准改用「设定的视口宽度常量 `w`」**（脚本里判断汉堡越界时用的就是常量 `w`，所以那条能抓到问题，溢出这条抓不到），或改用 `document.documentElement.clientWidth`。
→ 按此修正后，320 档 `/projects/` 应当如实报出约 44px 溢出（内容最小宽度 ≈364px），这正是当前被隐藏的真实问题。

#### N-20 L2 的 N-1 检查把 `type="hidden"` 计入 → 误报（v1.1.6 复核发现）
脚本选择器 `#contactForm input` 命中了 `<input type="hidden" name="product_name">`（`display:none`、不可聚焦、不可能触发 iOS 放大），其 computed `font-size` 为浏览器默认的 **13.3333px**，导致 5 个视口全部报 FAIL。
实测 `/contact/` 真实可见控件：`formName / formEmail / phone(无 id) / formMessage` **均为 16px** ✅ —— **N-1 实际已修复**，是断言写歪了。
→ **修复：选择器排除 `type="hidden"`**（现有代码只排除了 honeypot `tabindex="-1"`，不够）：
```javascript
Array.from(document.querySelectorAll('#contactForm input, #contactForm textarea'))
  .filter(el => el.type !== 'hidden' && el.getAttribute('tabindex') !== '-1')
```

### 6.2 L1 后端断言（零新依赖，必跑）

**命令**：

```python
def test_mobile_nav_contract(self):
```

CSS 规则断言若保留，**必须用正则约束"同一媒体块内"**，否则形同虚设：

```python
def test_mobile_nav_hidden_rule_present(self):

        css,
        r'@media[^{]*max-width:\s*767px[^{]*\{[^@]*?\.nav-links\s*\{[^}]*display:\s*none'
    )
```
- 断言 `collectstatic` 产物与源一致（可选）：`manage.py collectstatic --noinput` 后比对 `staticfiles/css/base.css` 含新增规则。

|---|---|---|---|
| 阶段一 F1'~F5'、F6、N-1/N-5/N-8/N-9/N-10 | L1（DOM 契约断言）全绿；**L2（Playwright/msedge）全绿**；既有测试零回归 | 手机（390）＋平板（768）逐页：汉堡可见可点、nav-links 隐藏、面板含 Contact **与语言/主题**、产品/项目首屏见内容、侧栏默认收起、无横向滚动 | **L1 + L2 + L3 全绿** → 可进入阶段二 |

### 6.6 与部署流程的衔接

```text
本地全绿（L1 + L2 + L3 全绿，其中 L2 跑本地 runserver 视口模拟）
  → 生产 URL 只读跑一遍 L2（防 DEBUG / 压缩 / 数据差异，见 §6.8.2）
  → 提交（该阶段一次性提交，含 F6 的 ?v= bump）
  → 推送到 Vercel Preview（预览分支）
  → 在预览环境用同一 §4 清单抽验（重点：collectstatic 产物、Whitenoise 缓存、?v= 版本号是否生效）
  → 确认无误 → 合并/发布生产（并打 git 标签）
```

- **每阶段只推送一次**（该阶段全部通过后），避免半成品上线。

- **部署后再跑一次 L1**（`manage.py test`，生产环境同样本）与 L3 核心页抽验；若发现回归，**立即回滚到上一发布版本（git 标签）**，回到对应阶段修复后再走上述流程。


### 6.7 常见问题与应对

| 情况 | 处理 |
|---|---|
| `collectstatic` 后样式未更新 | 确认 `?v=` 已 bump（F6）；浏览器硬刷新（Ctrl+F5）；检查 Vercel/Whitenoise 缓存头 |
| 本地全绿、生产异常 | 优先在 Vercel 预览环境复现；差异多来自环境变量（DEBUG、CSRF_TRUSTED_ORIGINS、ALLOWED_HOSTS）或缓存；Chrome 无痕 + 强刷复测 |
| Playwright 未安装 | **D4 已改判，L2 为阶段一必做**。Windows 上用 `channel="msedge"` 驱动系统 Edge，**无需下载浏览器**（见 §6.3）；连包都不想装时用 §6.3 的 Edge `--headless --screenshot` 零安装兜底 |
| 手机无法访问 `runserver` | **首选根本不用手机**：本地 runserver + Playwright 视口模拟（`is_mobile=True`），见 §6.8.1。确需真机时用 `0.0.0.0:8000` 启动；防火墙放行 8000 端口；确认同一 Wi-Fi；核对 `ALLOWED_HOSTS`（DEBUG 时自动允许本机/局域网） |
| 某档断点出现回归 | 记录截图与复现步骤 → 回到对应阶段修复 → **重新跑该阶段全部用例直至全绿** → 再继续 |
| Google Fonts 加载卡住（国内） | 见 N-5。本地验收前先改异步加载，否则实机测试会长时间挂起 |
| 本地 L2 全绿但生产仍异常 | 见 §6.8.2：多为 DEBUG / 压缩 / 数据差异。用生产 URL 只读跑一遍 L2 复验 |

### 6.8 还需要真机 / 部署后验证吗？—— L2 的能力边界

> **结论**：L2 **可替代约 80% 的部署后真机验证，且不需要部署**——本地 `runserver` + Playwright 视口模拟即可完成。但**不能 100% 替代**；真机应保留为"发布前一次性确认"，而不是每次改动的回归手段。

#### 6.8.1 本地直连：不部署、不用手机

```powershell
python manage.py runserver 0.0.0.0:8000
```

Playwright 访问 `http://127.0.0.1:8000`，并在 context 上设置：

```python
ctx = browser.new_context(
    viewport={"width": 390, "height": 844},
    device_scale_factor=3,
    is_mobile=True,      # 关键：启用移动端视口模拟
    has_touch=True,      # 关键：启用触摸事件
)
```

`is_mobile=True` 会让 Chromium **真正按移动端渲染**：`meta viewport` 生效、媒体查询按 390px 计算、`@media (hover: none)` / `(pointer: coarse)` 生效。

> ⚠️ 这与"把桌面浏览器窗口拉窄到 390px"**有本质区别**：拉窄窗口不改变 `is_mobile`，`meta viewport` 不生效、`:hover` 仍按桌面处理。手拉窗口测出来的"没问题"是假象——这正是 P0-1 一直没被发现的原因之一。

#### 6.8.2 但本地 ≠ 生产，这四个差异必须处理

| 差异 | 影响 | 处理 |
|---|---|---|
| `DEBUG=True` | 静态文件直出未压缩、错误页不同、`ALLOWED_HOSTS` 宽松 | 合入前用 `DEBUG=False` + `collectstatic` 本地跑一次 |
| 无压缩 / 无 CDN | 加载性能与字体阻塞体感不一致 | **性能类结论一律以生产为准** |
| 本地 0 延迟 | 掩盖慢网下的布局跳动（CLS） | 需要时用 CDP 限速：`cdp.send("Network.emulateNetworkConditions", {...})` |
| 本地 seed 数据 | 与线上文案长度不同，影响换行与截断 | 关键页用生产 URL 复验 |

**推荐折中**：Playwright **直接指向已部署的生产 URL 做只读回归**（只发 GET、不写库、不改数据，零风险）。既真实，又省掉本地搭生产环境的麻烦。

#### 6.8.3 L2 能覆盖什么 / 不能覆盖什么

**✅ 能覆盖（本方案全部 P0 与大部分 P1 都在此列）**

| 能力 | 断言方式 |
|---|---|
| 横向溢出 / 元素被裁切（P0-1） | `scrollWidth > innerWidth`；`boundingBox` 越界检查 |
| 断点是否生效（F1' nav-links 隐藏、F3' 面板含 Contact） | 可见性 + 面板内链接文本集合 |
| 汉堡是否被挤出（P0-1 伴生） | `boundingBox.right ≤ viewport width` 且可点击 |
| 实际渲染字号、触摸目标尺寸 | `getComputedStyle` / `getBoundingClientRect` |
| 侧栏默认收起 + 展开收起交互（F4'） | 点击后断言高度/可见性变化 |
| RTL（`/ar/`）溢出与方向 | `dir` 属性 + 溢出断言 |
| `prefers-reduced-motion`、深色模式 | Playwright 原生：`reduced_motion="reduce"`、`color_scheme="dark"` |
| 三档视口截图基线 | 截图 + 像素 diff，可无限重跑 |

**❌ 不能覆盖（约 20%）—— 及各自的替代验证手段**

| 项目 | 为什么模拟不了 | 替代手段 |
|---|---|---|
| **iOS 输入框聚焦自动放大（N-1）** | 这是 Safari/iOS 的 **UI 层行为**；Windows 上即使装了 Playwright 的 WebKit 也不保证复现 | **静态断言**：断言所有 `input/textarea/select` 的 computed `font-size ≥ 16px`。Chromium 上就能跑，且比真机更可回归 |
| `env(safe-area-inset-*)`（N-6） | 桌面浏览器下恒为 0 | **静态断言**：断言 Cookie 横幅 CSS 含 `env(safe-area-inset-bottom)` 且带非 0 fallback |
| `100vh` 与 iOS 地址栏收缩（N-11） | 依赖 Safari 动态视口 | 代码已用 `100dvh` + `100vh` 降级（`base.css:407-408`），断言二者**成对出现**即可 |
| 真实触摸/手势：双击缩放、长按菜单、`:hover` 粘滞 | 只能派发合成事件 | 真机点一遍（约 1 分钟） |
| 真实性能：手机 CPU 下 555KB hero 图 + 阻塞字体 | 本地桌面 CPU + 0 延迟完全掩盖 | 生产 URL + Lighthouse / PageSpeed **移动端档** |
| 键盘弹起挤压视口 | 依赖系统输入法 | 真机在联系页点一下输入框 |
| 微信 / WhatsApp 内置 WebView、国产浏览器内核 | Chromium 模拟不到 | 装对应 App 打开一次（外贸站建议至少测一次微信内置浏览器） |

> **关键洞察**：对 iOS 特有三项（N-1 / N-6 / N-11），正确做法**不是去模拟，而是断言"防御性写法是否存在"**。这比真机测试更可靠且可无限重跑——真机只能发现"这次坏了"，静态断言能保证"永远不会坏"。

#### 6.8.4 建议的验证流程

| 时机 | 做什么 | 成本 |
|---|---|---|
| 每次改动 | 本地 runserver + L2 三档视口 | 秒级，全自动 |
| 合入前 | 生产 URL 只读跑一遍 L2（防 DEBUG / 压缩差异） | 分钟级 |
| 发布前 | **真机 10 分钟**：iPhone Safari + 一台 Android（含微信内置浏览器），只测 6.8.3 表中"不能覆盖"的 7 项 | 一次性 |
| — | L3 人工清单中"必须真机"的项单独标注，其余一律交由 L2 | — |

这样真机从"每次都要"降为"发布前一次"，且只聚焦于机器测不了的部分。

> **何时做**：发布前一次，约 10 分钟。**本地 L2 无法代做**——涉及 iOS/Android 的 UI 层行为与真实 WebView。

## 8. 更优替代方案

### 8.1 导航：单一数据源 + 移动端"功能不减"

**核心思路：不要靠"隐藏"来腾空间，而是把功能搬进抽屉。**

```html
<!-- templates/includes/nav_items.html —— 唯一数据源 -->
<a href="{% url 'home' %}">{% trans "Home" %}</a>
<a href="{% url 'products' %}">{% trans "Products" %}</a>
<a href="{% url 'projects' %}">{% trans "Projects" %}</a>
<a href="{% url 'news' %}">{% trans "News" %}</a>
<a href="{% url 'about' %}">{% trans "About" %}</a>
<a href="{% url 'contact' %}" class="nav-only-mobile">{% trans "Contact Us" %}</a>
```

- 桌面 `.nav-links` 与移动面板**共用**该片段 → 永远不会再出现"面板少一项"。
- `.nav-only-mobile` 在 `≥768px` 时 `display:none`（桌面已有独立 `.nav-cta`）。
- 移动面板底部追加 **语言切换 + 主题切换**。
- 移动端导航条只剩 **logo + 汉堡**（≈200px），**物理上不可能溢出**。

> 收益：一次改动同时解决 P0-1、P0-2、N-2、N-3，且不丢失任何功能。

### 8.2 侧栏折叠：checkbox hack（替代 `<details>`）

```html
<input type="checkbox" id="sidebarToggle" class="sidebar-toggle-input">
<label for="sidebarToggle" class="sidebar-toggle-label">筛选 / 目录</label>
<div class="sidebar-nav"> ...分类树... </div>
```
```css
.sidebar-toggle-input, .sidebar-toggle-label { display: none; }        /* 桌面：常驻展开 */
@media (max-width: 900px) {
  .sidebar-toggle-label { display: flex; }                              /* 移动端：显示折叠按钮 */
  .sidebar-toggle-input:not(:checked) ~ .sidebar-nav { display: none; } /* 默认收起 */
}
```

**关键原则：把"展开"作为 HTML 默认态，"收起"作为增强态。** 反过来做（默认收起、靠 JS 展开）会让无 JS 用户永久失去分类导航。
备选（渐进增强）：HTML 不写 `hidden`，由 JS 在 `matchMedia('(max-width:900px)')` 命中时主动收起 —— 无 JS 时侧栏始终展开，退化为当前行为，不会变成"内容不可达"。

### 8.3 字号：`min/max` 替代 `clamp`，并限定在移动端作用域

```css
/* base.html 注入时保留原始值，命名 -admin */
:root { --fs-hero-title-admin: 3.5rem; --fs-section-title-admin: 2.25rem; }

/* base.css：仅移动端收口，桌面渲染路径零改动 */
@media (max-width: 767px) {
  :root {
    --fs-hero-title:    min(var(--fs-hero-title-admin),    max(30px, calc(1rem + 4vw)));
    --fs-section-title: min(var(--fs-section-title-admin), max(22px, calc(0.85rem + 2.4vw)));
  }
}
```

| 场景 | 原 `clamp(30px, 7vw, 56px)` | 新 `min(56px, max(30px, 1rem+4vw))` |
|---|---|---|
| 390px，后台值 56px | 30px | 31.6px |
| 768px，后台值 56px | 53.8px | 46.7px |
| 1280px，后台值 56px | 56px | 56px |
| **390px，后台值 24px** | **30px（与意图相反）** | **24px（尊重后台）** |
| 用户放大浏览器字号 | 不响应 | 响应（含 rem 基线） |

### 8.4 验收：用本机 Edge 做零安装 L2

| 方案 | 安装成本 | 可做断言 | 推荐度 |
|---|---|---|---|
| **L2-lite：`msedge --headless --screenshot`** | **零**（系统自带） | 仅截图 | 立刻可用 |
| **Playwright + `channel="msedge"`** | `pip install playwright`，**不下载浏览器** | 完整（可见性/点击/无横向滚动） | **推荐** |
| L3 纯人工 DevTools 逐档切 | 零 | 不可回归、易漏 | 仅作补充 |

最小可用用例（约 30 行，覆盖 P0 全部）：
```python
from playwright.sync_api import sync_playwright
PAGES = ["/", "/products/", "/projects/", "/news/", "/about/", "/contact/"]
SIZES = [(320,568),(390,844),(768,1024),(1024,768),(1440,900)]
with sync_playwright() as p:
    b = p.chromium.launch(channel="msedge")
    for w, h in SIZES:
        pg = b.new_page(viewport={"width": w, "height": h})
        for url in PAGES:
            pg.goto("http://127.0.0.1:8000" + url)
            assert pg.evaluate("document.documentElement.scrollWidth <= window.innerWidth + 1")
            if w < 768:
                assert pg.locator("#hamburgerBtn").is_visible()
                box = pg.locator("#hamburgerBtn").bounding_box()
                assert box and box["x"] + box["width"] <= w
                assert not pg.locator(".nav-links").is_visible()
            pg.screenshot(path=f"shots/{w}-{url.strip('/') or 'home'}.png")
```
