# 生产环境测试方案

> **一句话说明**：本文给出「测什么、用什么测、怎么算通过」。第 2 章是动手前的准备清单，
> 第 4 章是用例矩阵（可直接当检查表打勾），第 5 章是执行顺序，第 6 章是能不能上线的判定线。

## 0. 基线事实（2026-09-26 实测，非推测）

| 探测项 | 线上实际结果 | 对测试方案的影响 |
|---|---|---|
| `https://www.solaronelighting.com/` | 200，`Server: Vercel` | 站点存活，可作为测试入口 |
| HTML 响应头 | `Cache-Control: public, max-age=0, must-revalidate`，`X-Vercel-Cache: MISS`，`Age: 0` | **每次访问都回源函数**（对应清单 N-47）→ 性能用例必须记录冷/热启动差异 |
| `Vary` 头 | `/` 与 `/products/` 有 `Vary: Accept-Language`，但 **`/fr/`、`/es/products/` 完全没有 `Vary`**（已二次复核确认，非抓包抖动） | ⚠️ 潜在缓存键缺陷：若将来启用边缘缓存，可能把法语页返回给英文用户 → 用例 T-C4 专门盯它 |
| `/admin/login/` | 200，`Cache-Control: max-age=0, no-cache, no-store, must-revalidate, private`，`Vary: Cookie, Accept-Language` | admin 已正确禁缓存（后台功能测试安全） |
| CSP | 含随机 `nonce`，`frame-ancestors 'none'`，`script-src 'self' + googletagmanager` | 脚本注入类用例（T-F2）与 GA 加载用例（T-I1）共用 |
| HSTS | `max-age=31536000; includeSubDomains; preload` | 安全头基线已达标，仅需外部工具复核评分 |
| 裸域 | `https://solaronelighting.com/` → **308** 跳 www | T-A3 验证所有路径都跳（不只首页） |
| `sitemap.xml` | 200，`application/xml`，**53 个 `<loc>`** | T-C1 需核 53 条与后台已发布内容数一致 |
| GA4 | 已埋点：`templates/base.html:38` 异步加载 + `preconnect` | **重要**：外部统计已存在 → 清单 N-48 的「选项 A」实际上半只脚已落地，T-I1 要验证 GA 是否真收到数据 |
| 本地 `.env` | 只有 `SECRET_KEY` 一个键 | `CONTACT_NOTIFY_EMAIL` / SMTP 只在 Vercel 配置 → **测试询盘前必须先确认这些生产环境变量存在**（T-D1 阻塞项） |
| L2 自动化 | `playwright 1.62.0` 已装进 `.venv`，但 `scripts/e2e/run_checks.py` 的 `BASE_URL` 写死 `http://127.0.0.1:8123` | 生产自动化改造点很小（参数化 BASE_URL），但**不能直接复用**，见 §3 L4 |

## 1. 范围与红线

### 1.1 本次覆盖范围
- 生产站**公开页面**：首页 / 产品总览 + 产品详情 / 项目 / 新闻 / 关于 / 联系 / 404。
- 6 个语言版本（en 无前缀 + fr/es/de/ru/ar 前缀）。
- 询盘提交链路（表单 → 落库/发邮件）。
- 后台 `/admin/` 的**只读检查**（登录、列表渲染、字段显示）。
- 性能、SEO、安全头、兼容性、可观测性。

### 1.2 明确**不在**本次范围（红线）
| 红线 | 原因 |
|---|---|
| ❌ 不要把 Django 测试套件（`manage.py test`，140 条）指向生产 | 它带 `DATABASES` 写入与 seed 同步（N-42 的导出链路），会污染真实文件 |
| ❌ 不要在生产后台做「保存/删除」来验证内容变更 | 生产 DB 是 `/tmp` 临时盘：保存**不会上线**（真源是 `seed_data.json`），还会触发一次导出告警。内容变更一律走本地改 → `regenerate_seed` → 部署 |
| ❌ 不做压力/并发测试（不用 ab / locust / jmeter 打生产） | 会打到真实访客，且 Vercel 防火墙限流（`vercel-firewall-rate-limit.json`）会把它当攻击 |
| ❌ 不做渗透扫描（nikto / sqlmap / nmap 一类） | 属对他方系统的未授权扫描，且会触发风控封 IP。**需要的话必须先在 Vercel 面板加白名单再谈** |
| ⚠️ 询盘测试提交要留标记并善后 | 见 T-D2，测试数据必须可识别、可删除 |

### 2.2 本地工具（已具备）
- **Python 3.12 + `.venv`**（Django 6、Pillow、playwright 1.62）— 无需新装。
- **Microsoft Edge**（系统自带）— Playwright 用 `channel="msedge"` 驱动，**零浏览器下载**。
- **`scripts/e2e/run_checks.py`**（L2 响应式回归）+ **`visual_review.py`**（截图复核）— 目前只跑本地，本方案 L4 需要它支持 `--base-url`（改动约 10 行）。
- **Qoder 内置 browser-use**（可截图、取可访问性快照、读 console 报错、看网络请求）— 适合做「浏览器控制台有无红字」这类断言，不用装插件。
- `curl`（Git Bash 自带）— HTTP 头与状态码探测主力。

### 2.3 需装 / 建议新增（尽量少）
| 工具 | 装法 | 解决什么 | 优先级 |
|---|---|---|---|
| **Lighthouse** | 用 Edge 自带 DevTools（`F12` → Development → Performance/Web Vitals）**或**直接用下面 PageSpeed 免装 | 生产性能 Core Web Vitals（LCP/CLS/INP）数值 | P1 |
| **PageSpeed Insights**（网页版，免装） | pagespeed.web.dev | 移动端/桌面端 Lighthouse 评分 + 真实 Chrome 用户数据 | ✅ P1，推荐免装 |
| **securityheaders.com**（免装） | 在线扫 | HSTS/CSP/XFO 等打分，独立第三方佐证 §安全 | ✅ P1 |
| **GTmetrix 或 WebPageTest**（免装） | 在线 | **从海外节点**测首屏瀑布图（Vercel 边缘在新加坡/美国，国内访问需另测） | 🟡 P2 |
| **Network Analyzer / Ping 类 App**（手机） | 手机安装 | 从国内 4G/家庭宽带实测国内可达性（域名未备案时国内移动网络可能不稳） | 🟠 P2，但对你客户所在地很关键 |
| ❌ 不推荐装 | Selenium / Cypress / k6 / JMeter / Postman | 现有 Playwright + curl 已覆盖，多一套框架＝多一套维护成本 | — |
| ⏸ 可选 | Updown.io / UptimeRobot 免费档 | 上线后 7×24 可用性告警（**属上线后运维，不属本次测试**） | P2 |

### 2.4 生产配置确认（测试前置，不确认就别测表单）
> 对应清单 N-39（v1.5.7 已硬化代码，但「配环境变量」这一步一直挂着）。

- [ ] Vercel 环境变量已配：`CONTACT_NOTIFY_EMAIL`、`EMAIL_HOST_USER`、`EMAIL_HOST_PASSWORD`（+ 可选 `EMAIL_HOST/PORT/TLS`）。
- [ ] `SECRET_KEY` 已设且与部署环境匹配（清单 #13）。
- [ ] `ALLOWED_HOSTS` 含 `www.solaronelighting.com`（#4 已收紧，随机预览域名需另配）。
- [ ] `DATABASE_URL` 当前值确认 —— 若仍是 `sqlite:///tmp/db.sqlite3`，则**询盘只靠邮件**，T-D3 的判定标准随之改变。
- [ ] Vercel Firewall 速率限制规则是否已按 `vercel-firewall-rate-limit.json` 启用（#5）。
- [ ] 记录当前**线上版本号**（页面/后台某处显示 `APP_VERSION`，应为 `v1.8.1`）与 Git commit，作为本次测试基线。

## 3. 测试分层（沿用项目已有的 L1/L2 叫法，往上补三层）

| 层 | 手段 | 打生产？ | 说明 |
|---|---|---|---|
| **L1 单元/集成** | `python manage.py test`（140 条） | ❌ 只在本地/CI | 上线前置门禁：必须全绿才允许部署 |
| **L2 本地端到端** | `scripts/e2e/run_checks.py`（Playwright + Edge，8 视口 × 6 页） | ❌ 本地 | 响应式契约回归，已在 §0 引用 |
| **L3 生产黑盒 HTTP** | `curl` 批量探测：状态码、跳转、缓存/安全头、URL 规范化 | ✅ | **性价比最高**，可脚本化、可重复 |
| **L4 生产浏览器实测** | Playwright 指向生产 URL（需给 L2 加 `--base-url`）+ Qoder browser-use 截图/console | ✅ | 真渲染、真网络、真 JS |
| **L5 外部服务视角** | PageSpeed / securityheaders / Search Console / 手机 4G 实测 | ✅ | 站在全世界看这个域名 |

**关键补充**：L3/L4 建议统一收进一个**新脚本** `scripts/verify_production.py`（读 URL 清单 → 跑断言 → 输出 PASS/FAIL 表），避免每次手工 curl。这是本方案唯一建议新增的代码（约 150 行，不碰业务逻辑）。**当前阶段先不写，等方案定稿**。
